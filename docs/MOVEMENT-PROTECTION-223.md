# 2.1.223：距离口令与传感器报错修复

## 用户报告

2026-11-26，LOOI 放在地面，说“走10厘米”后回复“传感器保护，禁止移动”。本次先读取手机与底座状态，不自动重试行驶。

## 已确认的代码缺陷

1. 本地距离语法原本只接受“往前走10厘米”等带方向的说法，不接受“走10厘米”。后者会落到模型理解流程。现在完整、独立的“走X厘米/公分/毫米/米”按向前处理，“退后X厘米”按后退处理；仍需唤醒或有效续聊窗口，否定句、叙述句及复合任务不触发本地移动。距离仍由2至500厘米范围检查和定位导航处理，不是按固定时间假装走够距离。
2. 中文动作控制器遇到任意异常，都可能拿上次 `lastMotionBlockReason` 覆盖真实错误。已删除这个覆盖；真实传感器阻断由底层当次抛出带原因、方向、状态的 `LooiMovementBlockedError`，地图、连接、参数与停止写入失败保留原始错误。
3. 底座页原本优先把历史阻断显示成当前保护。现分开显示当前状态、前进/后退各自状态与历史阻断，并为防跌落、近障、传感器未就绪、边缘锁存提供中文说明。

没有修改传感器阈值、FED9 字节解释、方向性保护、边缘锁存清除条件或停止写入机制。

## 排查支持

增加仅可通过既有 DUMP 权限 ADB 接收器调用的只读 `robot_diagnostics` 探针。可按 robot/stt/llm/navigation 分类与事件名子串过滤，最多40条，限制输出长度。它不调用模型，不发运动指令，不导出 Key 或原始录音。

真机保留记录已核对（时间为北京时间）：

- 11月25日19:13:51，右转请求被 `cliff-turn` 拦截。
- 19:13:56，四路地面标志恢复为 `11111`。
- 19:14:01，语音记录了一次 move 请求，154毫秒后仍回复旧的 `cliff-turn`；没有新增 movement-blocked 记录。
- 当前手机存有9张地图，全部 `active=false`。旧距离准备流程调用 `currentHomeId()` 会抛出“请在家庭地图选择当前地点，再安排行驶”；旧控制器会用上述旧的 `cliff-turn` 把它盖掉。这个地图状态已用实际 `currentHomeId()` 纳入回归用例。旧版没有记录覆盖前的原始异常，因此不能恢复当次唯一的原始异常文本，但上述覆盖路径和当前地图准备失败均已复现。

因此已确认存在旧转向错误覆盖距离准备错误的路径，不应把它归因于10厘米距离本身或直接关闭防跌落保护。

此外修复了地图准备入口：距离请求不再提前调用会抛错的选图函数，而是交给家庭导航统一准备。没有当前地图时弹出“请选择当前所在地点”，用户选择后将原始距离请求排队；恢复实际定位并确认当前连接的最低姿态后才执行。取消选图不排入新动作，不自动猜测、切换地点或创建替代地图。家庭导航按钮也使用同一选图流程，避免因无当前地图而连选择页面都打不开。已有唯一当前地图则沿用它。

距离定位导航仍需要选择实际地图并恢复定位、确认姿态；本次没有把这项准备条件跳过或假装已经行驶。

重新手动连接后，手机报告驱动通道就绪、当前保护允许位为 safe，未锁存边缘；防跌落完整帧尚未收到。这不等于完成了实车地面安全验收。
