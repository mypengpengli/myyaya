# 首个 APK：Hermes 文字任务联调

日期：2026-10-27。开发方案已具备实施条件，本次先完成直接连接现有 Hermes 的最小闭环。最终 Pi / NewAPI 主线保持不变；本阶段不要求先部署新的 Pi 服务。

## 本轮范围

- 默认进入已有表情界面，不要求上游 OpenAI Key。
- 设置中首次填写独立 Hermes Token，保存在手机 SecureStore；安装包不预置任何服务密钥。
- 首页“执行任务”进入横屏任务面板：左侧主区域显示任务、公开执行进度和最终文本，右下保留小丫表情。
- 能力发现后提交任务；本地 SQLite 先保存固定请求体和 UUID 幂等键，再发起网络请求。
- SSE 支持 `data` JSON 中的 `event`、命名事件、分块 UTF-8、CRLF、多行 data 和注释保活。只记录公开中间说明、工具和子任务生命周期，不记录隐藏推理。
- 保存 run_id；返回表情、网络断开、Android 结束进程后，重开通过状态接口恢复，已知 run_id 的任务不重新提交。
- 停止请求的 `stopping` 与最终 `cancelled` 分开显示；晚到的查询不覆盖已确认的终态。
- 提交响应丢失时，用户主动重试沿用原请求体和原幂等键；超过 23 小时保守阻止未确认提交的再次发送，避免越过服务端幂等保留期。更换地址或 Token 不会自动重派旧任务。

联调构建 profile 为 `hermes-integration`，省去当前没有使用的上游俄/乌/英 Vosk 离线模型资源，并关闭旧 Realtime 入口；完整构建仍保留原模型插件。联调 APK 仍包含原生设备模块，不能把未做的真机验证当作硬件验收。

## 已验证

- TypeScript 与任务专项行为测试通过：真实 SQLite 读写、重建服务后的恢复、响应丢失重试、凭据绑定、停止确认、终态竞争和分块 SSE 解码。
- 通过本轮客户端的真实 HTTPS 测试：提交只读 `pwd` 任务、收到最终结果；重复同一幂等键返回同一 run_id；收到 `tool.started`、`tool.completed`、`run.completed`。
- 实测任务编号：`run_286f3cda7fbc4a6f90373096d78bde92`。测试没有改动服务器文件或配置。
- 本地 ADB 当前没有连接的 Android 设备；安装、手机网络、原生 SecureStore、前后台恢复与 BLE 需要手机验证。

可重复运行电脑接口联调：`python scripts/check-hermes.py --run-smoke`。它从当前 Windows 用户凭据管理器读取 Token，经 stdin 传给实际客户端测试，不把凭据写进文件、命令行或输出。

## 手机验收顺序

1. 安装 APK，确认可以进入表情界面。
2. 设置 → Hermes 服务器连接，填写独立 Token，点击“保存并测试连接”。服务地址已预填。
3. 返回首页 → 执行任务，输入“运行 pwd，只读检查当前目录，并用中文回答”。
4. 查看工具执行进度、最终结果和右下角表情；点击“返回表情”后再次进入，任务仍在。
5. 新任务执行期间切出应用、重新进入，确认根据原 run_id 继续查询。关闭页面不等同停止服务器任务。
6. 验证“停止任务”先显示正在停止，再显示服务器实际终态；验证断网时的明确提示及恢复。
