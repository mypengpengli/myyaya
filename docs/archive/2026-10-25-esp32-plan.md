# K50 桌面机器人

目标：使用自己的红米 K50 作为屏幕、摄像头、语音和 Android 应用主机，使用 ESP32-S3 控制机器人动作，并接入自己的 NewAPI 模型服务。

智能体还需要能调用手机的本地功能。其中，录像与视频播放是明确需求：可以录制视频，并根据用户指令找到、播放录好的视频。“取出录像”在这里指找到并播放录像。

## 当前方案

```text
红米 K50（Android 应用）
    │ BLE
ESP32-S3 N16R8
    │ UART
微雪 Bus Servo Adapter (A)
    │ 单线串口总线
HD1910 × 2
```

配件清单来自用户分享的方案，尚未通过实物照片逐项确认：

- K50：使用用户已有手机；保持现有 Android 系统。
- ESP32-S3 N16R8：已焊排针，具体开发板型号和 USB 接口待确认。
- 飞特 HD1910 × 2。
- FE-URT2 调试板和微雪 Bus Servo Adapter (A)。
- 2S 7.4V 电池、固定输出 5V / 4A 的 UBEC、配套线材和万用表。

## 手机功能调用需求（待实现）

K50 的 Android 应用需要把手机功能提供为智能体可调用的工具。智能体理解用户指令后，由应用执行实际操作并返回结果，界面同步显示录制或播放状态。

首批视频能力：

| 能力 | 预期行为 | 指令示例 |
| --- | --- | --- |
| 录制视频 | 开始录像、停止录像并保存，提供录制状态和已保存视频的引用 | “开始录像”“停止录像” |
| 查找录像 | 找到本应用录制的视频，支持按最近一次或录制时间选择；存在歧义时让用户选择 | “找到刚才录的视频” |
| 播放录像 | 在手机屏幕上实际播放选中的视频，并播放视频自带声音 | “播放刚才录的视频”“播放最近一次录像” |
| 控制播放 | 暂停、继续及停止当前视频播放 | “暂停”“继续播放”“停止播放” |

视频访问范围首先覆盖本应用录制的视频；手机已有视频通过用户选择或授予访问权限后纳入播放范围。具体权限与前后台行为在确认 K50 系统版本后实现。

验收时需要完成一次实际闭环：录制并保存一段视频 → 找到该视频 → 通过用户指令在 K50 上播放 → 暂停和继续。录像未找到、权限不足或播放失败时，应返回实际失败原因。

## 第一次连接

1. K50 开启开发者选项中的 USB 调试，用数据线连接电脑，解锁并允许本机调试。
2. ESP32-S3 先单独用 USB 连接电脑。
3. 运行 `powershell -ExecutionPolicy Bypass -File .\scripts\check-devices.ps1`。

当前连接检查只读取 USB 设备、串口及 Android 系统型号/版本，不刷写固件，不发送舵机动作，不读取手机个人文件。

第一轮检查不接舵机电池、UBEC 或舵机。等核对实物接口、舵机规格及线序后再接外部电源。开发板的 USB 与外部 5V 是否可以同时使用，需要依据该板原理图确认。

## 实施顺序

1. 确认 K50 的 ADB 连接和 ESP32-S3 的 USB/串口。
2. 核对主板、转接板、舵机及电源实物；确定 UART GPIO 和 D/V/G 线序。
3. 单独连接一个舵机，先读取型号、ID、位置等信息；随后确认两个舵机的独立 ID。
4. 无负载、小范围、低速测试动作。
5. 加入 ESP32 BLE 通信和 K50 Android 按钮控制。
6. 接入表情、语音识别、语音合成及 NewAPI。
7. 实现手机本地工具调用，完成录像、查找录像、播放录像及播放控制的闭环。
8. 根据实测再增加本地唤醒、人脸跟踪和其他工具。人脸身份识别、声纹与精确声源定位不属于首次联调验收范围。
