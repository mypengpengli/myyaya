# 195：分段行驶采集，不再被地图高度漂移卡住

用户指出：通行候选为0不应该让开发一直停在静态算法上，应在已确认的空地里实际走、停、观察，再决定下一段。本版为这项实测增加单独入口。

## 修复的实际问题

194实车准备时，用户已确认底座连接、脖子最低、后摄方向约50厘米空地及线缆余量。录像已启动，但地图坐标中的相机高度随后漂移约3.27厘米，倾角只变约0.09°。地面参考失效后，点选450毫秒标定的回调抛出未捕获异常，App闪退。日志定位到`TaughtRoutePanel.confirmCalibration`。**当时没有发出行驶指令，不能写成实车三段采集成功。**

195接住延后执行的标定菜单错误，条件变化时显示原因，不让异常退出App。正式地图导航仍保留原有地面/定位条件；新增的人工空地采集使用实时相机会话位姿，不依赖地图锚点高度、已测通行候选或完整路线。

## 使用方式与边界

在真实平整地板上，把整机装稳、脖子保持最低，人工确认后摄方向约50厘米无障碍且线缆有余量。手动连接底座，打开教路线相机并开始实时扫描，然后开启“录制相机与IMU（本机）”。

进入“教路线与复走 · 操作”→“空地分段采集（450毫秒）”。确认场地后，有三声提示和倒计时，朝后摄看到的方向执行一次450毫秒后退并停止。记录停止后的画面约1.5秒；观察新画面后再次选择该入口，启动下一段。**每轮最多三段，每段都需单独启动，不会自行连走三段。**

这条流程监测新鲜相机数据、定位、连接修订号、相机俯仰/横滚、录像状态和已有障碍提示。断连、倾斜超过约6.9°、定位丢失、录像停止、进入回放或相机会话变化会终止。暂停界面和停止按钮也会终止，重连后不能沿用旧的人工确认。该流程没有抬头/回正指令。

地图高度变化仅记入诊断数据，不能据此认定脖子移动。记录的位移、转角和高度变化仍来自ARCore会话估计，不是尺量真值，不作为导航标定通过。结果明确标记：未验证米制导航、未声明深度空地、停车来源为限时指令回执。未知区域保留未知，不会被写入已测通行图。

这为现场采集提供可执行路径；通用自动地面识别、近障触发停车、探索目标选择和自主绕障仍需分别实现及验收，不能把人工确认场地的三段运动写成自主导航已完成。
