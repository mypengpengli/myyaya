# 底座动作与相机：2.1.155

2026-10-28。当前为本地正式签名联调包，已覆盖安装到小米 12 Pro；公开 Release 仍为 2.1.152。全部需求的缺口见 [功能完成度](FEATURE-COMPLETION-2026-10-28.md)。

## 底座的实际调用链

模型调用 `connect_robot` / `robot_action` → 手机工具注册表 → 既有中文动作控制器 → `looi-robot.ts` → 社区 `@sourcebug/looi-sdk` → `react-native-ble-plx` → 底座。没有另写一套电机协议。

| 通道 | 用途 | 沿用的指令 |
| --- | --- | --- |
| FED0 | 轮子，两字节、无响应写入 | 前进 `7707`、后退 `86fc`、左转 `047a`、右转 `0082`、停止 `0000` |
| FED1 | 头部 | 抬头 `00`、回正 `87`、低头 `ff` |
| FED9 | 底座通知 | 交给现有传感器解析和运动保护 |

服务为 `000000ff-0000-1000-8000-00805f9b34fb`。前后动作各约 450 毫秒，左右沿用社区时间估算的 90 度；这些不代表精确里程或导航。模型只能选择已有动作，不能自行生成原始蓝牙帧或连续盲走。

本地停止、后台停止、传感器保护和超时停止仍优先。新的直接动作会打断尚未完成的模型调用，避免旧回复随后再次驱动。连接工具只使用用户已保存的底座，不自动选择陌生设备。

蓝牙扫描已修复：ble-plx 的 `BleManager` 是进程共享实例，扫描结束只停止扫描，不能销毁客户端，否则会连带取消正常 GATT 会话。

## 拍照与看环境分开处理

| 用户意图 | 实现 | 屏幕行为 |
| --- | --- | --- |
| “帮我拍张照片” | `phone_photo`，复用社区 Camera2 原生 `captureStill` | 眼睛移到左侧，右侧显示照片；可确定、重拍、取消。确定后保存并将图片交给模型，恢复表情 |
| “看看我面前有什么” | `observe_scene`，拍摄真实画面作为模型图片输入 | 不打开照片确认框或 Viewer；模型直接回答。保存的观察图片可在后续明确要求时调出 |
| “录一段视频” | 既有 `record_video` / 原生录像通道 | 眼睛靠左、录像预览靠右；手动停止后保存。尚未增加录像后的确定/重拍步骤 |

默认前摄对应屏幕面向的一侧，后摄对应手机背面，不宣称看到了整个房间。系统相机权限照常申请；小米实机已授权。正在录像、应用在后台或前一拍摄尚未结束时不抢占相机。

拍照确认前不保存、不上传。重拍丢弃上一帧；取消、退出、后台、两分钟超时或任务中止后，不允许迟到的回调重新弹出照片或上传。确认保存失败保留当前预览供重试。
