# 小丫产品需求基线

日期：2026-10-27。范围：小米 12 Pro / 澎湃 OS 3、LOOI 底座、自有 Android APK、现有 Ubuntu Hermes。
本轮补充：手机不固定为 12 Pro，也可能使用红米 K50；按 Android 系统和实际设备能力适配。首次启动、授权、设备连接与表情主界面的新增要求见 [陪伴交互说明](COMPANION-UX.md)。
状态：开发方案需求基线；本文记录目标与验收口径，不表示相关能力已经实现或通过真机测试。
本文优先反映本次用户确认；总体背景见 [PLAN.md](PLAN.md)，Pi 技术方案见 [PI-AGENT-PLAN.md](PI-AGENT-PLAN.md)。
“用户已明确的需求”与“默认补充约定”分开记录；默认项用于补齐交互细节，后续可调整。

## 一、用户已明确的需求

### R01 固定唤醒与童声

- 固定唤醒词为 **“小丫小丫”**，唤醒后进入中文对话。
- 首版希望使用可爱小孩声音，后续可扩展或更换音色。
- 用户本次已同意另配 Azure Speech，首选采用普通话儿童女声 `zh-CN-XiaoyouNeural`（晓悠）；尚未试听或接入，需要独立 Speech 资源凭据及区域配置，不能使用现有中转 Key 代替。

### R02 日常全屏表情

- 日常陪伴和对话以全屏机器人表情为主，复用社区项目已有表情与动画。
- 监听、思考、说话、执行和异常状态应与真实会话事件对应。

### R03 拍照、多轮改图与图生视频

- 支持拍照后围绕同一张图片连续说“这个表情换成……”等指令，完成多轮图生图编辑。
- 支持继续指向当前图片或改图结果，说“让这个人跳舞”等指令，提交图生视频任务。
- 会话应保留最近图片、各次编辑版本及父子关系，能明确本轮使用哪一版；原图与旧版本仍可调出。
- 图生图与图生视频是需要落实的目标，当前尚未实测其输入图片、任务提交和结果协议。

### R04 统一文件与媒体查看器

- 图片、本地媒体、Word、PPT、PDF 等使用统一 Viewer 入口，按内容类型展示或预览。
- 左上角有固定按钮，并支持语音“固定”；右上角为关闭 X；右下角显示默认 10 秒倒计时。
- 固定后保持当前内容展示；关闭只隐藏展示，不删除文件或产物记录。
- 支持随时说“打开刚才的文件/图片/视频”重新调出相应内容。

### R05 视频完整播放与关闭时机

- 视频应可完整播放，播放结束后额外保留 10 秒，再按未固定状态自动关闭。
- 暂停、拖动进度、缓冲、加载或播放恢复时，不能被过期倒计时提前关闭。
- 时长未知或无法确认播放结束时，不启动可能截断播放的错误倒计时；保留手动关闭和固定。

### R06 同 App 展示与持续会话

- 表情、媒体和任务页面是同一 App 内的视图切换。
- 展示内容时监听和智能体继续在前台工作；切到媒体页面不代表把 Android App 退到后台。
- Android 锁屏、真正切到其他 App、后台运行等行为另做系统适配与真机验收。

### R07 Hermes 工作画面

- Hermes 执行时，任务大框占左侧或上方主要区域，右下角保留小表情，布局遵循用户草图。
- 展示可公开的步骤、工具活动、日志、任务状态，以及服务确实提供的截图或画面。
- 不把原始隐藏推理当作展示内容，也不把日志伪装成真实截图；真实画面能力取决于 Hermes 接口。

### R08 长任务期间持续对话

- 视频生成、Hermes 等长任务执行时，仍可继续日常对话与其他独立操作。
- 多个结果完成后进入队列，不抢占用户正在固定查看的内容。
- 重启后仍保留任务和产物引用，能够重新找到已完成结果；引用失效时给出真实状态。

### R09 语音运动与停止

- 支持语音控制前、后、左、右与停止。
- 手机本地运动控制器统一仲裁动作、持续时间、冲突和停止；停止优先于正在执行的运动。
- 具体方向、速度、停止表现和底座指令映射以 LOOI 实机结果为准。

### R10 认人、看向、靠近、跟随与房间记忆

- 人脸与身形认人、按声源看向人、靠近人、跟随人，均为产品目标。
- 支持记住“客厅”等地点，并最终理解和执行“去客厅”等请求。
- 按检测、身份、方向、距离、跟随、地点与导航逐级验收；不能假定手机麦克风天然具备可靠 DOA 声源定位，或现有底座已经能导航。

### R11 手机自主与 Ubuntu Hermes 分工

- 尽可能由手机自主完成日常陪伴、感知、本地媒体、设备控制和可承载的智能任务。
- 办公、浏览器操作和手机难以完成的任务派给现有 Ubuntu Hermes。
- Hermes 返回文件或结果后，由手机展示并汇报；需要接入的真实 API 与任务能力另行核对。

### R12 微信、邮件与未来插件

- 未来支持通过插件给指定微信联系人发内容、发送邮件等扩展能力。
- 区分 Android 系统分享面板与具备合法可用 API 的自动发送；能够分享不等于能自动发给指定联系人。
- 权限按具体插件和能力申请、记录与撤销；不能在首次启动一次性请求最大权限。
- 联系人选择、账户授权、发送确认和失败反馈需在实际插件接入时定义。

### R13 指定中转与模型

- 中转地址固定为 `https://apichat.jiazhuangai.com/v1`；凭据使用私有配置，绝不写入本文、源码、日志或 APK。
- 主对话与看图候选：`agnes-3.0-flash`；生图候选：`agnes-image-2.5-flash`。
- 生视频候选：`agnes-video-2.5`；ASR 候选：`TeleAI/TeleSpeechASR`。
- 文字聊天、语音转写、TTS、图片生成/编辑、视频任务使用各自适配器和真实端点，不能都发送到聊天端点。
- 现有模型列表与 HTTP 探测不能证明存在 TTS 或 Realtime 能力；图生图、图生视频与完整 Pi 工具循环仍需验证。

### R14 原有需求继续保留

- 手机录像、查找与播放录像、本地已有媒体、相机看图、长期记忆与人物资料继续保留。
- 2026-10-27 用户调整：首版允许点击画面上的“停止录像”按钮结束。优先保证有声录像与保存、播放；录制时暂停中文识别，结束后恢复。录制期间的语音停止不再是首版验收门槛。
- 保留自有签名 APK 在线更新；同包名、同签名、递增 versionCode，升级保留设置、记忆和媒体索引。

### R15 即将到货的硬件与系统

- LOOI 即将到货，目标手机运行澎湃 OS 3。
- Android 具体 API 级别、底座固件与 BLE 行为、相机/音频并发、中文唤醒和系统 TTS 均待实机核对。
- 方案中的硬件能力标记为待验收，不能用模拟器或 HTTP 成功替代整机通过。

## 二、默认补充约定

- **D01 产物与展示分开：** 产物记录拥有稳定引用；Viewer 的显示、固定和关闭是界面状态，删除需独立明确操作。
- **D02 计时起点：** 图片或文档成功可见后开始 10 秒；视频由真实播放结束事件触发额外 10 秒。固定时不自动关闭，取消固定后重新计时。
- **D03 视频计时恢复：** 暂停、缓冲和拖动时清理关闭计时；恢复播放后等待本次真实结束。重播也按新的结束事件计时。
- **D04 结果队列：** 当前内容固定、正在操作或正在播放时，新结果只提示并入队；用户可语音选择下一项、指定任务或调出刚才结果。
- **D05 图片指代：** 优先使用用户当前明确选中的图片版本；否则使用当前会话最近确认的图片。存在多个合理目标时先澄清，不静默换图。
- **D06 图片版本：** 每次改图保留独立 artifactId、父图片引用与版本号；图生视频记录使用的确切图片版本，完成顺序不应改变既有指代。
- **D07 短对话与长作业：** Pi 工具提交长任务后立即返回任务 ID；作业执行器独立跟踪，完成事件进入队列，避免视频生成长期占用 Agent 循环。
- **D08 取消边界：** 停止说话、取消当前对话、取消外包任务、停止录像、停止底座运动分别处理；“取消已申请”与“实际已停止”分开显示。
- **D09 可替换声音：** 使用独立 TTS 适配器与音色配置；系统中文 TTS 作为经真机确认的降级，不能把提高音调视为已实现童声。
- **D10 前台资源协调：** 同一音频管理器协调唤醒、ASR、TTS、媒体与录像，复用现有能力并验证回声、抢占和打断；原生能力由 Kotlin 模块承担。
- **D11 最小首版部署：** 保留 React Native/TypeScript 应用，服务使用 Node/TypeScript 模块化单体与持久任务表；后续依据真机证据逐步提高手机自主程度。
- **D12 外部操作权限：** 插件声明所需账户、数据与操作范围；系统分享及外部 API 调用分别验收，访问权限不能自动扩大为发送权限。
- **D13 能力分级：** 未通过方向、距离、障碍与停止验证的能力保持“待支持”；先记录真实限制，再决定具体传感器或实现方式。

## 三、关键验收场景

- **A01 唤醒与声音：** 说“小丫小丫”唤醒并以候选童声应答；播放自身声音不误唤醒，唤醒/打断后不继续播过期回答。
- **A02 多轮图片：** 拍照→改成笑脸→再改一种表情→让图中人跳舞，逐步指向正确版本；能重新打开原图与任一中间版本。
- **A03 文件展示：** 分别打开图片、Word、PPT、PDF 和本地视频；固定、语音固定、X 关闭、超时隐藏与再次调出均有效。
- **A04 视频边界：** 播放超过 10 秒的视频，暂停、拖动、缓冲、恢复及重播均不提前关闭；结束后保留 10 秒；未知时长也可持续播放。
- **A05 多结果与重启：** 固定一份文件期间完成多个任务，只排队提示；取消固定后可选择结果；重启仍可按原任务打开产物。
- **A06 Hermes 并行会话：** 办公或浏览器任务运行时继续聊天；主区域显示真实可用进度/画面，小表情持续工作；完成文件回到手机。
- **A07 运动停止：** 逐项验证前后左右、连续命令冲突、断连与停止；模型或服务器忙碌时本地停止仍生效。
- **A08 感知导航分级：** 分别验收已登记人与陌生人、人脸/身形混淆、声源方向、靠近、跟随及客厅导航，每项单独记录通过条件与失败表现。
- **A09 原有能力：** 有声录像→手动停止→保存→查找→播放→恢复中文对话；记忆保存/检索/修改/删除与重启；APK n→n+1 保留用户数据。
- **A10 插件能力：** 系统分享与 API 自动发送分别演示；指定收件人、所需权限、取消授权与发送失败均有明确反馈。

## 四、待用户或接口补齐的信息

- **Q01 童声：** 用户已选 Azure Speech / 晓悠，待配置独立 Speech 资源的区域与凭据并试听；凭据只进入服务端私有配置，音色仍可替换。
- **Q02 中转媒体：** 核对图生图、图生视频的请求字段、图片格式、任务 ID、查询/取消、结果保留时间及访问方式；未验证前不承诺可用。
- **Q03 Hermes：** 已提供 `https://hermes.jiazhuangai.com`，用户验证 Runs/SSE 真实任务；本机只读鉴权/能力检查通过。手机联调 Token 首次手填后存 SecureStore，APK 包/源码不预置；底层模型凭据留服务器。待验手机网络、派单、文件与截图回传；详见 [接入契约](HERMES-INTEGRATION.md)。
- **Q04 LOOI 与手机：** 到货后记录型号、固件、Android API 级别及权限行为，验证 BLE、音频、相机、持续监听和运动停止。
- **Q05 空间与身份：** 明确认人登记方式、目标场景、跟随距离、客厅标记方法与可用感知条件，在实测后确定具体技术。
- **Q06 文件与分享：** 确认可用的 Word/PPT 转换或预览后端，以及微信/邮箱目标账户和可用插件/API；无接口时保留手动分享路径。
- **Q07 保存与恢复：** 确认手机/服务器产物保留期限、容量与备份方式；当前按“隐藏不删除、重启可找回引用”设计。
