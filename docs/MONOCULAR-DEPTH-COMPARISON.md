# 现成单目模型对照：从191实拍数据选择替代视觉来源

## 已完成的电脑实验

使用[Depth Anything V2官方项目](https://github.com/DepthAnything/Depth-Anything-V2)对应的[Android移植项目](https://github.com/shubham0204/Depth-Anything-Android)模型发布`model-v2`，选`fused_model_int8_256.onnx`。模型27342208字节，SHA256 `4806aca888e2c118e93295db15d6b8341428a27885996711e923a3720b440138`；Android参考源码固定`f4adf9918b13db754fcf83fd7d8553f8f6d55b58`。Small模型与实现许可证需随正式分发保留；本轮模型只存本地忽略目录，没有作为仓库或APK资产发布。

按模型实际输入验证为RGB `uint8[1,256,256,3]`，输出为`uint8[1,252,252]`。使用标准RGB行序，不照抄移植代码中的R/B/G排列与列序遍历；直接检查本机推理图像的方向和边缘对应关系。

四张真实画面包括189罐子前后、191转向前后。模型输出的罐子、柜子、轮子与地板轮廓目视对应；电脑CPU四线程约420～474毫秒/张。这不是小米手机耗时，也不是有标注集的检测准确率。模型输出为按图归一化的相对深度，不能直接当米数。

利用实测镜头高度10厘米与记录的相机方向，在人工指定的一块下方地板区域拟合`1/Z = a × relative + b`，再检查未参与拟合的相邻地板区域。四图训练区约99.8～100%满足该实验残差条件，验证区推算高度绝对残差中位数约1.1～4.2毫米。该结果依赖“这两块区域确为水平地板”和原相机姿态，没有独立量尺验证；不能称为全图毫米精度，更不能据此证明障碍距离或可通行区域可靠。它只支持继续做手机与多场景验证。

本地证据：`.tools/191-monocular-comparison.json`、`191-monocular-comparison.jpg`、`191-monocular-floor-calibration.json`及四份相对深度数组。原视频、模型和画面未上传。

另用RGB中的红色罐体区域检查候选高度：两图罐顶约12.33/12.04厘米，约85～87%的罐体像素高于拟定3厘米障碍阈值。没有对罐子实际量尺，因此只说明前后图结果相近、值得做独立尺寸验证，不是已验证障碍高度或漏检率。见`.tools/191-can-height-hypothesis.json`。

## 192手机只读性能入口

发现现有`@siteed/sherpa-onnx.rn`已提供通用`OnnxInference`和JNI/C运行库，优先复用，不新增第二份ONNX运行库。

192新增DUMP权限保护联调中的`probe monocular_depth`，只读本机固定目录`navigation-probe/monocular-benchmark`内已核验的模型和四份256×256 RGB输入，保存四份相对深度输出并返回耗时。校验文件尺寸、输入/输出类型与形状、常量输出；正常和失败均释放会话。没有相机、网络或电机调用，不是面向用户的导航模式。模型由ADB先核验主机及手机SHA256后放入，尚未开发正式模型下载/导入流程。

192首轮手机已运行到输出，随后Expo文件系统拒绝写入由ADB建立的外部诊断子目录。这是输出存储失败，不能登记整轮性能通过。修订为写入应用缓存，同时返回完整输出SHA256和16×16抽样像素，便于核对手机/PC结果。修订包正在重新构建，手机耗时与整轮输出仍待验收。

若通过，再开发实时图像取样、地板校正与障碍观测，不把PC结果当成手机完成。
