# 222：中断后逐项复核

2026-11-25。221 曾通过构建并安装，但不能据此判定计划全部完成。用户追问后，本次重新检查需求、原计划和真实调用链，确认并继续补了下面的遗漏。221 保留为旧候选包，不作为本次修正的验收依据。

## 复核发现的实际遗漏

| 遗漏 | 实际原因 | 222 源码修正与证据 |
| --- | --- | --- |
| 全屋探索没有记录可查询的见闻照片 | 探索计划未返回 `inspectionId`，执行器里的记录分支不会启动；这不是“等真机再验收”，是调用链缺失 | 从原生任务到计划、拍摄、持久保存、返回后分析全部接通。新增 `home-exploration-mission.test.mjs` 跑真实探索执行器，检查停车拍摄、原地扫视、返回、照片区域关联和最终任务状态 |
| 接近观察点时可能提前换下一个目标 | 从附近巡视迁移代码时保留了“等停车”的变量，却没有实际用来阻止推进 | 必须收到 `WAYPOINT_REACHED` 或 `VIEW_READY` 且停止回执为真，才拍摄和继续。执行器回归故意延迟停车回执，验证不会抢跑 |
| 房间多或路线稍长就无法巡视 | 原生计划仍限制 6 个地点/40 米，JS 路线也限制 40 米，任务时长还保留旧值 | 同步改为最多 64 个登记观察点、200 米路线；单轮巡查最多 20 分钟，原生驱动/录像期限配套。达到边界保存未完成任务，不冒充已返回。新增 8 个房间、48 米往返测试 |
| 地点表满时返回规划失败 | 返回路线通过增加一个临时地点实现，已有 128 个地点时会超过容量 | 改为沿已有连接选择实际返回路线，不再插入额外地点。新增满 128 地点的返回用例 |
| 探索统计和位移回执没有真正保存 | JS 发了 `exploredCells` 和估计位移，但原生进度字段白名单漏掉；探索统计还沿用了起点附近的局部缓存 | 使用全局网格的实际统计，保存探索时间、观察格数、估计位移和目标误差；界面不再用附近缓存冒充全局进度 |
| 房间改名可能把旧任务排成“刚执行” | 更新照片所属房间时顺带刷新了任务执行时间 | 区域编号和名称同步时保留原任务时间，观察时间也不变；补了时间顺序与独立地图隔离断言 |

自动分房或照片关联失败现在保留具体原因。照片已经保存但未成功归属房间时，不再静默吞掉错误。

## 语音原问题复核

- 固定套话已删除；公开中间回复、实际工具阶段、等待与失败事件可播报。导航的播报也交给当前监听会话，避免另外的 TTS 绕开回声和打断处理。
- 指定距离从估时动作转到定位目标；准备成功和物理到达分别处理，不能先声称已走完。参数支持其他距离；实际误差仍需尺量。
- 拍照采用取景确认、审片确认两阶段；重拍/确认优先走本地，不必等待 Flash 模型。
- 长句支持可调停顿、片段保留、“听我说完/说完了”，以及可选中转识别、失败回退和旧结果取消。
- 长任务保留任务号、真实阶段和错误信息；播报进度不等于服务器任务取消或结束。
- 周围短巡游与全屋探索是两个明确入口；222 修复后，全屋探索也保存实际观察照片及时间，而不是只有地面图。
- 没有同一人的近处/1 米/2 米录音结果，无法认定错词已经全部解决，更不能据此判断必须更换麦克风。
