# 房间地图：扫描、保存与地点

地图实现版本：2.1.171；2.1.172 增加实物照片的四角校正与预览。该页面已经从传感器探针扩展为本地表面建图，仍不包含自主行驶。

## 使用

1. 173 起可从左滑菜单 → **房间地图** → **打开房间地图**；设置中的原入口保留。
2. 点 **新建地图**，输入“客厅”等名称。旧地图切换前会保存；不要在扫描中移动固定参照物。
3. 若希望下一次找回位置，首次扫描前点 **设置参照图**，选择固定平面照片/海报的原图。174 起也可点 **用后摄拍摄**，调用系统相机拍下实物，确认后直接进入校正页。拖动四角贴合图像边界，排除墙面、桌面与白边；输入实际图像宽、高，**校正并预览 → 登记此图**。选的是单张平面图像，不能用整个房间的照片代替。
4. 点 **开始扫描**，人工缓慢带手机观察房间。使用后摄；页面暂停原有对话与视觉服务、停止并断开底座连接，不会自行驱动履带。
5. 右侧显示观测表面俯视图、黄色相机轨迹；绿色圆点和方向线只在当前定位有效时显示。网格间距 1 米。可点 **标记地点**，将当前相机位置命名为“沙发旁”等。
6. 点 **保存地图**；扫描时每 15 秒自动保存，离开页面时也会保存。**导出地图** 可保存 `.yayamap` 原文件，其中包含表面点、轨迹、地点和已登记的参照图。
7. 重新进入后点 **打开地图**。无参照图的旧地图可以查看，但不能恢复位置或追加扫描。已有参照图时点开始扫描，将后摄对准同一位置的实物图像；保持整图可见约两秒，定位有效后才显示当前位置并继续融合。

地图保存在应用内部目录 `files/room-maps`，覆盖升级保留，卸载会删除。当前没有导入外部地图、删除地图、自动跨房间合并或语音导航工具。

175新增[地面、障碍和候选通行判断](TERRAIN-ANALYSIS.md)：先填写整车长宽高，扫描并点选确认实际地面，再显示本次会话的短期观测。原表面地图在右侧下方，局部判断图在上方。历史表面点和未知空白仍不代表可通行；新增绿色也只是几何候选，不授权底座自动行驶。

## 固定参照图的边界

采用 ARCore Augmented Images，输入图片不少于 300×300 像素，建议有丰富、不重复的纹理。初次识别时参照图需占画面至少约四分之一；不适合二维码、简单图形和重复纹理。实际图像宽度支持 5～300 厘米；填错尺寸会影响地图比例。[官方要求](https://developers.google.com/ar/develop/augmented-images)

实物照片应清晰、尽量正对拍摄，校正无法恢复失焦或模糊丢失的特征。Google 官方 `arcoreimg eval-img` 建议得分至少 75；SDK 能接受图片不代表该图足够稳定。173 实物短扫描仍未重新检测；导出地图 CRC 正确、参照 JPEG 可解码，但该校正图评分为 0，属于待排除的质量风险。174 增加现场拍摄入口和已配置图库数量诊断；没有在 APK 内集成桌面评分工具，也不声称能自动保证图片合格。[官方评分工具](https://developers.google.com/ar/develop/augmented-images/arcoreimg)

拍摄先保存当前地图、暂停并释放 AR 相机，再由系统相机拍摄；未确认校正前不修改原参照图。拍摄临时文件在应用私有缓存中，读取后清除，仅将确认后的校正图存入地图。已扫描地图不允许更换参照图，请新建测试地图，避免旧坐标关系失效。

只接受相机 TRACKING 且参照图 FULL_TRACKING，至少三个稳定采样、持续不少于一秒，再建立本次会话锚点。参照图姿态只用来对齐地图；离开画面后由本次 ARCore 会话继续定位。相机跟踪丢失时清除当前位置、断开轨迹，并重新等待参照图。移动参照物、相同图片重复张贴、错误实物尺寸均可能产生错误对齐，本版本没有能力自动识别这些情况。

这是**固定图像辅助定位**，不是 RTAB-Map 无标记回环重定位。RTAB-Map 官方 Android 工程仍使用独立 CMake/Ant 打包链，本次未接入其库或地图数据库。[官方工程](https://github.com/introlab/rtabmap/blob/master/app/android/CMakeLists.txt)

172 的四角校正使用 Android `Matrix.setPolyToPoly` 做确定性的透视变换，保留原图特征；先按照片 EXIF 纠正方向，再按实物宽高比例生成校正图供确认。宽高均为 5～300 厘米、宽高比 1:5～5:1。交叉/重叠/照片外的四角和过小选区会拒绝，校正结果最长边 1600 像素、短边至少 320 像素。用户实际量取尺寸仍是比例正确的前提。[Android Matrix](https://developer.android.com/reference/android/graphics/Matrix#setPolyToPoly(float[],%20int,%20float[],%20int,%20int))

## 数据和计算

- 原生 Kotlin 内计算，2 Hz 融合，不逐帧上传服务器、不经过 JavaScript 传送点云。
- 仅使用 Raw Depth + 置信度图，阈值 153/255（约 60%）；投影采用 textureIntrinsics，与传感器深度原始坐标对齐，保留下采样源像素步长。相机坐标 +X 右、+Y 上、-Z 前。[官方投影示例](https://github.com/google-ar/arcore-android-sdk/blob/main/samples/raw_depth_java/app/src/main/java/com/google/ar/core/examples/java/rawdepth/PointCloudHelper.java)
- 仅融合新时间戳且距当前相机帧不超过 250ms 的数据，距离限定 0.2～4m。5cm 体素，最多 60,000 个体素、8,000 个轨迹点、128 个命名地点；地图范围限定相对原点各轴 ±25m。
- 文件带版本号、长度限制、CRC32 校验，使用 AtomicFile 替换。损坏文件拒绝加载；坐标、参照图关系和创建会话一起保存。
- 未设参照图时坐标只对创建它的 ARCore 会话有效。新 Session 不会借用旧数值假装定位成功。
- 这是观测到的**表面点集合**，不是可通行占据地图。点云中的空白、稀疏深度和黑色区域都不等于没有障碍；黄色轨迹也不是验证过的可行驶路线。

阈值与范围是研发包的初始过滤条件，不代表已完成精度标定。170 的平滑深度曾出现可疑大值，本次不使用平滑深度生成地图。

## 验证与后续

几何、原始像素采样、时间戳去重与时效、跟踪丢失、跨会话坐标失效、参照坐标恢复、文件完整性与地点持久化有原生单元测试。真实手机的扫描、保存和重开结果另记入版本验收；单元测试不代表实物参照定位误差合格。

171 最终包已安装，短程采集、升级后地图恢复（1534 个表面体素、117 个轨迹点）、地点冷启动恢复和 `.yayamap` 导出/CRC 校验已通过。实物参照图定位尚未验收；详见 [手机记录](PHONE-CHECK-2026-10-30.md)。

后续实物试验已完成首次 FULL_TRACKING、地图对齐和参照坐标下的地点保存；冷启动后地图/地点能恢复，但目标重新检测当时仍为 NOT_SEEN，尚不能标跨会话定位通过。173 用本会话全部已知图像替代低频的单帧变化查询，并将保存的参照关系与当前对齐状态分开；该修补不保证解决所有观察条件下的首次检测问题。

174 在同一固定实物前重新拍摄、校正并登记新地图 Coupon174，首次对齐和三次结束进程后的重新检测均取得 FULL_TRACKING，恢复 Desk174 地点与有效位置，图库实际配置数量为 1。其中前两次视角基本不变，第三次在用户左移约20cm后从新位置启动，恢复198个表面体素并定位成功；导出保留42个轨迹样本及原地点，CRC正确。更大范围的不同起点、遮挡恢复、独立精度和整房间覆盖仍需验证。新图桌面评分仍为0，所以没有将评分判定为旧图失败的唯一原因，也不会用低分一概否定实际成功检测。

下一步仍需要：真实参照图跨会话定位误差与失败样本、已知距离标定、底座安装高度近场视野、闭环漂移、长时间温度/帧率、地面与障碍区分、机器人外参、倒车速度/停止距离和规划控制。当前没有“去客厅”自动执行入口，不能把已保存“客厅”地点解读为已完成自主导航。
