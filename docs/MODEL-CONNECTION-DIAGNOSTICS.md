# 手机模型请求与中转后台对账

## 169 的修正

168 显示的“模型回复等待超时”由手机的计时器触发，不能证明 NewAPI 或上游模型记录了服务端超时。此前没有保存文字对话的服务端请求号，无法事后精确对账。用户反馈后台没有超时后，已撤回对中转服务的归因。

169 为每次文字 HTTP 请求记录客户端编号、UTC 开始时间、请求字节数、收到响应头的时间、HTTP 状态、服务端请求号、首字节时间、接收字节数、数据事件数、是否收到结束帧，以及超时发生的阶段。记录不包含 Key、请求正文或模型回答；可从诊断日志导出。客户端编号以 `X-Client-Request-Id` 发出；是否在后台显示取决于服务器日志配置，优先使用响应里的 `x-request-id` / `x-oneapi-request-id` / `request-id`。

受 Android 权限保护的联调入口支持 `probe chat-http`，读取最近 24 条请求阶段记录，不发起模型请求。`probe stream` 只检查首个数据块，不能当作完整回答通过；普通 `probe chat` 和真实 Pi 对话需分别确认。

## 根据证据定位

| 手机记录 | 能说明什么 |
| --- | --- |
| 等待响应超时，没有 status / requestId | 手机未在等待窗口内取得响应头；不能据此认定服务器没有收到请求或已经失败 |
| HTTP 200，有 requestId，但接收阶段超时 | 请求已有正常响应头，需要按同一编号核对正文、网关转发和手机接收；HTTP 200 不代表完整回答已收到 |
| receivedBytes > 0、结束帧未出现 | 检查断流、帧格式和客户端解析，不把不完整文字当作完成 |
| complete / completionSeen=true | 客户端已解析终止帧，不再等待连接关闭；这是一次完整请求，工具任务完成需另查真实状态 |

等待限制仍为单次请求空闲 60 秒、总计 180 秒，本版没有靠扩大等待时间来掩盖问题。成功或结束后显式取消原生请求，避免只取消 JavaScript 读取器却让原生连接继续读。兼容 CR / LF / CRLF，以及终止 JSON 完整但没有最后换行的中转流；自动化测试保留了截断回复必须失败的约束。

生成工具已返回有效任务回执后，即使后续模型回答失败，小丫也会用本地回执说明任务已建立、后续回复未收完整，不再只提示重新生成。回执不代表服务端已经完成，也不重发生成请求；用户主动停止时不以回执覆盖停止。新一轮对话不复用上一轮回执。

单元测试覆盖终止帧缺换行、跨字节中文、原生取消迟迟不返回、请求无响应头 / 有响应头但无正文、请求号与隐私字段，以及派单后的模型失败不重复执行工具。实机结果以[手机续测](PHONE-CHECK-2026-10-29.md)为准。

## 本轮实机结论

真实手机普通 Pi 回复、按主题找回并固定旧纸飞机、查询既有 2K 小猫任务三项通过，没有新增媒体任务；四次 HTTP 请求均为 200 且解析到完整结束帧，单次约 7.3～31.2 秒。当前未复现旧超时。手机留在旧纸飞机原图的固定展示页。此前纸飞机的 2K 改图仍保持 unknown，未重新生成；新的声学与手机 OTA 验收边界不变。

最慢这次正常请求在约 30.9 秒时收到响应头，31.2 秒完整结束；仅凭后台没有超时或返回 HTTP 200，不能反推客户端已经及时收到完整回答。历史超时没有足够请求级证据，保持未定结论。
