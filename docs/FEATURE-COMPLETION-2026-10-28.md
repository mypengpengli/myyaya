## 当前版本仍应完成的开发

以下是原有使用过程的一部分，**不是因为难测就移到下一代硬件**：

1. 媒体多版本指代继续完善；媒体播放/暂停/进度控制和本地文件导入已补代码，待相应手机验收。
2. Hermes 文件接收、PDF/Office 内容预览及原文件独立保存已完成手机闭环；继续完善完成结果衔接和汇报的实际语音验收。Office 完整排版由手机办公应用处理，不作为服务器转 PDF 的开发阻塞。
3. BLE 重连修复后的动作接入与状态恢复；录像/媒体/语音资源交接和明确的错误恢复。
4. 继续使用已确认的系统中文 TTS，完成与媒体/识别的资源协调；不因缺少 Azure 资源拖延当前开发。
5. Tavily 接入本轮完成后再集中验证；后续按以上模块先补开发，再做相应的真机验收，避免反复要求用户为尚缺实现的流程测试。

文件交付的已通过项见 [手机验收](PHONE-CHECK-2026-10-28.md)；其余缺口仍按本表记录，不据此宣布原始需求全部完成。

## 测试与交付口径

- 先完成所声明模块的功能，再做必要的源码/协议/打包检查，最后做手机和整机测试。
- 联调 APK 可以提前交付，但必须标明剩余功能，不能将“测试中”当作尚无实现的替代说法。
- Tavily 请求依据[官方 Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)，固定发送到官方 HTTPS 地址；不会使用模型中转 Key，也不会把搜索 Key放进源码、模型上下文或安装包。
- 公开 Release 与当前开发/手机安装版本分开记录；本轮尚未自动发布新 Release。
