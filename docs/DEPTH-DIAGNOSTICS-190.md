# 190：未就绪双深度诊断与地图高度失效说明

基于[11月10日四次实体动作](PHONE-CHECK-2026-11-10-FIELD.md)。版本 2.1.190 已通过手机只读回放验收；自主导航尚未完成。

## 修改

- `RoomMapPanel` 不再在诊断入口丢弃未初始化的原始样本。两路的缺失、时间戳、数据新鲜度、非零/0.2～4米像素数量和距离中位数均进入报告；固定参考面可用时也会执行融合对照，明确报告拒绝原因。
- 地形融合仍要求原初始化条件。诊断报告不提供运动授权，缺失或不可信的平滑深度不变成空地。现有局部原始观测和导航脉冲限制保持。
- 本地深度记录升级为 schemaVersion 2，允许某路缺失、参考面尚未建立、原始时间戳过期或为零。按帧时间限速，避免“等原始深度有效才开始采集”的循环条件。
- 开始相机/IMU录像时同步新建 360 帧上限的深度记录，覆盖90秒录像；地板取样区菜单也可单独重新录制，用于无电机回放。原自动诊断仍默认120帧，保留文件数有界。
- `NavigationPoseLock` 和标定结果区分地图高度变化、相机倾角变化和连接变化。地图高度变化仍中止测量，但不再把它说成机械抬头，也不把未完成的位移作为车速标定。
- `summarize_depth_capture.py` 分别统计缺失、全零、过期和近处有效数据；`audit_replay.py` 兼容旧 v1 和新 v2，跳过缺少原始数据或参考面的记录，不补造参考面。

## 验证

175 项原生测试通过（头部7、导航168），含实际第二次动作的地图高度/倾角数值回归。新增 Python 记录摘要4项测试、TypeScript 检查和导航控制/取消回归通过。[完整源码CI](https://github.com/mypengpengli/myyaya/actions/runs/42746196885)通过。

190 保留数据覆盖安装并核验 APK 摘要后，回放189刚采的90秒直行/转向录像，全程无电机接口。实际写入276帧 schema v2：276帧未就绪记录、25帧未建立参考面记录；这些以前无法记录。原始样本全部为零，只有2帧时间戳仍新鲜；平滑深度191帧有0.2～4米范围数值。没有成对的近处原始证据，不能把平滑数据作为已验证距离，也未放行导航。回放深度由 ARCore 重新计算，不等同于当时实车的逐帧深度真值。

本地证据：`.tools/190-depth-replay-summary.json`、`190-unready-depth.ndjson`、`190-depth-availability-summary.json`。回放结束后已回到暂停的导航父界面并恢复 USB 全局常亮原值0。此轮没有190实体运动，也没有头部指令。

120毫秒左转约1.7°的问题未在本修订中扩大动作时长；后续明显转向测试需要独立安排，不能声称这一版已经完成了角度闭环。
