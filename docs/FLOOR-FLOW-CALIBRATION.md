# 地板光流与短动作标定

2.1.187 增加地板光流诊断，用来对照 ARCore 平移结果。它还没有参与自主导航、自由空间判断或标定通过判定。

## 188 开发：可核对取样区与拒绝原因

188增加“选择地板取样区（黄框）”：保留原下部范围，提供更低中央范围和可填写边界的自定义区域。区域以CPU图像坐标定义，再经ARCore转换到实际预览坐标，避免直接按屏幕比例猜测裁剪位置。更改区域会停止当前路线操作、清除原光流参考，报告附带区域及参考时间；黄框始终只是人工地板假设，不是地板分割或空地证明。

光流拟合新增明确的拒绝原因：一致特征不足、低内点比例、尺度或旋转超限、退化分布、无效对应点。原12内点、0.65比例、尺度及旋转界限不放宽，拟合细化后还会重新检查内点；被拒绝的结果不发布平移量。新增5项原生测试，162项原生测试通过；构建完成，尚待安装和回放验收。

用户将A4纸铺在地板并压平，底座未再移动。已保存第二段静止录制，以21×29.7厘米和人工核对的四角作平面PnP对照，候选高度约10.4厘米、重投影RMS约1.87像素，支持原10厘米量级。角点是低分辨率图像上的近似选择，纸面、畸变和模型仍有误差；这不是精确尺量，更不能证明前一轮行驶距离或自动替换手机标定。该段ARCore曾处于PAUSED，PnP只使用图像内参和纸张几何，不拿失效的位姿做移动测量。

新增离线工具`plane_scale_audit.py`，不调用电机或网络；3项合成投影测试覆盖米制高度、坏角点、错误尺寸次序及非法输入。输入JSON包含`imagePoints`（远左、远右、近右、近左）、`imageFocalLength`、`imagePrincipalPoint`，运行示例：

```text
python mobile/scripts/navigation/plane_scale_audit.py --input corners.json --width 0.21 --length 0.297 --output scale.json
python -m unittest discover -s mobile/scripts/navigation -p test_plane_scale_audit.py
```

该工具只适用于此轮近水平镜头、已知平整矩形假设，输出几何拟合候选；手机运行时尚未接入自动纸张识别和标定。方法参考[OpenCV平面单应与位姿说明](https://docs.opencv.org/4.13.0/d9/dab/tutorial_homography.html)，图像内参与相机物理位姿的区别见[ARCore Camera文档](https://developers.google.com/ar/reference/java/com/google/ar/core/Camera)。

## 187 真机对照结果

用户手动连接后，只读确认FED1仍为`0000`，重力方向与此前最低姿态基本一致。实际启动OpenCV和光流成功，初始约388个跟踪特征；选择保持当前位置，无头部动作。

本轮仅执行一次人工450毫秒后退。屏幕三秒倒计时已截图，动作结束后方向判据通过：ARCore位移约3.92厘米、沿后摄方向约3.90厘米、偏航约0.70°。动作期间姿态锁、地面、连接有效。用户随后明确确认：**看到了移动并停下，脖子没变**。本轮实际移动、停止与头部保持通过；提示音是否听见未单独验证。软件通过不是实测距离或完整自主导航验收。

光流在动作前有效、动作后拒绝。离线同一录像、同一高度及判据复核：原下方区域最终内点比例约0.50；收窄为图像横向30%～88%、纵向80%～95%的更低地板区域后，最终约0.77，69个估计中63个通过。该区域估计主要沿视线约7.7厘米，与ARCore约3.9厘米不一致，尚无独立实测尺度。画面包含鞋、罐子等非地板对象，结果支持排查地板区域混入不同表面；一次区域对照不能证明这就是唯一原因，也不能直接把新范围硬编码为可靠地板。

停止动作后ARCore地图相机高度继续漂移，偏离锁定值约17.7厘米，姿态锁按原判据失效，后退通过标记随之撤销，没有开始复走。手机重力方向前后只变化约0.8°，未发送头部指令；不能把地图高度变化解释成脖子实际升降。录像与日志已保存到开发机，地图保存，相机主动暂停，保持导航控制租约以免环境动作回正。

下一步先做可明确选择/检查的地板区域和失败原因诊断，对照独立尺度后再考虑地面约束里程计；本轮没有放宽0.65内点比例或导航放行门槛。

## 为什么增加一条视觉测量

186 在真实木地板上执行一次 200 毫秒后退。头部保持最低，姿态锁和地面参考有效；ARCore 报位移约 2.57 厘米，其中沿后摄方向约 1.48 厘米，方向比例约 0.575，低于现有 0.7 校验门槛，因此拒绝标定。用户没有注意到这次短动作，确认脖子未变，要求下一次动作更明显并提前提示。

录像中地面纹理有位移。用固定 10 厘米镜头高度、相机内参和 ARCore 旋转投影地板特征，离线估计主要沿视线移动约 3.3～3.5 厘米。另一段没有发电机指令的录像，光流结果接近静止，而 ARCore 地图坐标仍有厘米级漂移。这支持继续排查平移估计，不能据此断言实际距离已校准。

原始深度近处仍不足，曾出现中位深度约 20.9 米；增加光流不会自动补齐近处障碍、落差或整车足迹覆盖。

## 手机实现

- OpenCV 4.13.0 随 APK 本地打包；后台单线程跟踪灰度图，立即关闭 ARCore CPU 图像，不在工作线程持有 Frame。
- 使用图像下方限定区域作为人工地板假设，角点与双向光流筛选对应点；按实测固定高度和相机旋转投影到水平面。
- 相似变换 RANSAC 检查内点数、比例、尺度和旋转。特征不足、帧间隔过大、过期或加载失败均单独报告。
- 报告包含参考/样本时间、位移、内点比例、残差和固定高度；每条结果均标明 `autonomousMotionAuthorized=false`。
- 这不是自动地板分割。下方区域被物品遮挡、地毯起伏、头部高度变化或整机被拿起时，固定高度假设可能不成立；拟合残差不是实测距离精度。
- 标定记录同时保存动作前后光流报告。比较位移时必须检查参考时间相同、数据新鲜且拟合有效；重新选取参考之后不能直接相减。

## 更明显的一次人工动作

后退标定可选 200 或 450 毫秒，开始前有三秒可取消倒计时和三声媒体提示音。倒计时结束后重新检查定位、实际地面、固定头部、连接、障碍和控制通道。450 毫秒只用于明确确认的一次人工后退标定；普通导航脉冲上限仍为 250 毫秒，转向未扩大。

失败不自动重试，不放宽原方向判据。先对照录像、光流和 ARCore，再决定是否引入地面约束里程计。低头速度诊断已在 186 获用户确认到达水平最低，但日常 `head_down` 和导航“降到最低”仍是原单字节角度模式；此次导航采用“保持当前位置”。

## 可复核的离线工具

开发机安装 `opencv-python-headless` 和 `numpy` 后运行：

```text
python mobile/scripts/navigation/floor_flow_audit.py recording.mp4 --pose-log probe.ndjson --height 0.10 --output-dir audit --start 2 --end 20
```

要求录制对应的原生位姿日志，包含图像内参、旋转、帧时间和数据集文件名。工具输出 CSV/JSON。它独立于手机实现，当前离线验证环境为 OpenCV 5.0.0，手机使用 4.13.0；两者结果仍需对照，不能假定完全等价。私人录像和日志不入库。
