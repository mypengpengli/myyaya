# 房间视觉探针：第一步开发与验收

日期：2026-10-30。实现版本：2.1.170。导航选型见 [手机优先方案](PHONE-FIRST-NAVIGATION.md)。

## 当前交付

设置 → **房间地图 · 视觉探针** → **打开视觉探针**，进入独立 Android 页面。使用 AR Optional；没有 AR 服务也能继续使用原有聊天、媒体与 LOOI 控制。

- 显示后摄画面、AR 服务/权限状态、跟踪状态与失败原因、相机 XYZ 位姿与平面轨迹。
- 开始前可选择原始深度或平滑深度；运行时显示实际启用模式，配置不支持时明确退回可用模式或仅位姿。
- 原始深度按置信度过滤，黑色表示未知；预览保持传感器图像方向，不伪装成与屏幕画面对齐的障碍地图。
- 记录相机/深度时间戳、深度新采样或重投影、有效比例、距离统计、相机内参、帧率和 Android 热状态。
- 暂停、切后台和退出时停止 AR 采集，清除当前深度预览与有效位姿；轨迹不跨跟踪中断连线。
- 导出 NDJSON 记录，不保存或上传相机照片/视频，不调用任何模型接口。

此处是**相机轨迹与传感器探针**，不是机器人底盘位姿、可通行地图或跨会话定位。没有接入 RTAB-Map，没有自主运动工具，也不会尝试倒车、转身或抬头。

## 用户提出的倒车路线

已确认需求：屏幕面对用户，后摄朝底座后方；LOOI 不能单独左右摇头，机身可原地转向。因此后续首选验证：

1. 手机固定安装、固定俯仰；导航时以后摄朝向作为观察与行驶方向，对应底座倒车。
2. 将路径切线方向、相机朝向、底盘朝向和 SDK 命令分别标定，不把“前进”文本统一替换为“后退”。
3. 到达位置后先停车，再规划单独的机身转向，使前屏朝向指定交互点或经过确认的用户方向；不能对每个目标都无条件旋转 180 度。
4. 旋转前检查整个底座与手机的扫掠范围；行驶/转向中不混入社交自动抬头、点头与转身。

需要验证后向悬崖标记、后摄近场/低矮障碍覆盖、倒车停止距离与履带转向滑移。现有前向 ToF 不因软件倒车而变为后向测距。前后方向问题有了可行的设计路线，但仍不能据此开放自主倒车。

## 资源与生命周期

打开入口先取得外部 Activity 租约、释放社交相机、停止现有运动并暂停 App 语音/身体运行时；原生 Activity 完成并返回后再释放租约、恢复前台运行时。租约覆盖整个 Activity 生命周期，避免沿用应用的后台五秒退出策略导致采集半途结束。

AR 帧留在 Kotlin/GL 线程；界面和记录约每 500ms 更新一次。AR 服务包 `com.google.ar.core` 独立安装，不打进小丫 APK；SDK 固定 `com.google.ar:core:1.48.0`。页面包含 Google ARCore 的服务条款与隐私政策说明。

调试记录在应用专属 `navigation-probe` 外部文件目录；`latest.json` 为最新汇总，每次打开生成独立 `probe-<UUID>.ndjson`。保留最多五次记录，每次最多 3000 条，达到上限后继续显示现场状态但停止追加；导出包含汇总和已有采样。它们只是诊断，不作为保存地图或恢复行驶的依据。

## 验证方法

先检查未安装、权限拒绝、相机占用等失败入口；进入真实采集后再验证：

1. 静态下相机画面正常，跟踪/深度状态如实变化。
2. 人工缓慢平移手机，确认不是只有转动时的假位移；比较实际距离与相机轨迹。
3. 遮挡、暂停、切后台后，旧位置和深度不继续标为有效；恢复后轨迹断段。
4. 原始/平滑模式分别采样，核查置信度、无效区、时间戳与重投影记录。
5. 导出后检查记录可解析，退出探针能回设置，原有功能能恢复。

纯 Kotlin 深度读取测试覆盖平面行距、像素间距、非零 buffer 起点、无效深度、低置信度、无符号毫米值、采样尺寸边界和截断输入。生成 Android 工程后运行：

```sh
./gradlew :navigation-probe:testReleaseUnitTest
```

本项目生成的 Android 工程在配置阶段要求现有发布签名环境，即使只运行该测试也需沿用构建环境；不要为绕过检查把签名密码写到源码。
