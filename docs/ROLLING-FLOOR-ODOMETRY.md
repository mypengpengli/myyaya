# 189 地板视觉接续

这一版修复188只消耗起始特征、丢完后重新从零取样的结构问题。仍是只读视觉诊断，不驱动底座、不替代障碍/落差观测，也未接入自主复走。

## 实现

每次位移拟合通过后，把当前有效地板投影作为下一局部参考，在ARCore共同的重力对齐XZ基底中累计该段镜头位移。使用相机旋转和人工高度，不使用ARCore平移；结果不是RoomMapper地图坐标，也不是履带中心的位姿。

特征采用4×3网格分布。通过原有12内点、0.65比例、尺度和旋转条件后，剔除几何外点；不足480点时在当前区域补充，最多600点。新点只能依附已经通过的局部参考。匹配窗口改为31像素、4层金字塔，双向误差门槛不变。

原起点与局部参考分别记录：`originTimestampNs`固定，`referenceTimestampNs`表示本次连接来自哪一帧，`acceptedLinks`、`featuresAddedTotal`等用于核对接续。如果中间只有拟合失败而点身份仍能运输，之后可用同一参考重新拟合整段；失败帧不发布累计位置。如果特征耗尽、图像尺寸变化或帧间隔过长而必须重新取样，就标记`originContinuity=false`，不再发布原起点累计位置。新片段接近零不能解释为回到原点；只有明确重设视觉起点才能开始新的独立计量。

异步库加载或工作线程延迟超过250毫秒时，丢弃已变旧的输入，避免把启动时的陈旧帧设成起点。报告还包括工作耗时，供手机上核对是否因算力或帧间隔丢失。UI新增中下部建议区域和明确的重设视觉起点；仍需人工核对取样区确实是平整地板。

累计误差、人工高度误差、旋转误差、地板反光、非平面和动态物体仍可能影响结果。没有可靠连续性时保持未知，不允许靠补点“补出”已漏测的位移。

## 电脑原型对照

使用同一批私人录像和相机旋转日志，参数接近Android实现，原型OpenCV为5.0.0，手机为4.13.0。电脑结果不是手机验收，也不是独立尺量精度：

| 录像 | 有效估计 | 拒绝 | 末端估计 |
| --- | ---: | ---: | --- |
| 11月10日450毫秒动作，8～55秒 | 469 | 0 | 约6.9厘米 |
| 11月9日450毫秒动作，8～35秒 | 270 | 0 | 约7.6厘米 |
| 未发电机指令的静止对照，2～20秒 | 180 | 0 | 约0.6毫米 |

这些对照没有重新取样归零来掩盖失跟。实际Android还有内点筛选、网格占用和线程调度差异，必须再用手机回放确认。

目前170项原生测试（7项头部、163项导航）通过；TypeScript、导航动作所有权/取消和头部观测回归通过。覆盖连接修订号变化、快速重连、旧头请求取消、累计链接、错误引用拒绝以及重新取样后不冒充原点。最终APK与手机回放验收仍在进行。

## 断连后头部确认

用户明确观察到断连后脖子会稍微抬起，并愿意手动压回最低。189不再信任跨断连的最低姿态锁：BLE状态变化增加连接修订号，即使断连/重连都发生在两帧之间，也会使原确认失效，需要用户压回最低后重新选择保持当前位置。

同时取消断连前排队的头部动作，并补上一个表情动作在延时后回中的检查，避免旧动作跨重连继续写头部。对应行为回归包含排队头指令、延迟回中及快速重连最低锁失效。现有断连清理路径没有直接抬头帧；尚不能证明用户观察到的机械上扬由哪一条路径引起，也没有声称固件回位已修复。

当前阶段不需要人为按脖子或移动底座；新包先用已保存录像做无电机回放。后续实车前重新确认最低姿态与镜头高度。
