# 小丫语音、拍照与底座动作修复计划

**开发基线为 2.1.218（`eb1d4d5`），候选版本为 2.1.219。**目标是在一次候选包中交付以下改动，再由主人集中试用。文中的时间、距离误差和识别率目标用于开发验收，实测后记录结果。

## 一次正常使用应该是什么样

1. 主人一口气说“小丫小丫，帮我拍张照片”。小丫听全指令，左边保留眼睛，右边出现实时取景。画面跟着人动，主人可以慢慢摆姿势。
2. 主人说“确定”，小丫才按快门。看到定格照片，说“重拍”就回到实时取景；也可以点按钮。再次取景后，要再确认一次才拍。只有在定格照片上说“确定”，才保存这张照片。
3. 主人接着说“你把这张照片……里的背景换成海边”。中间停半秒，小丫继续听；说完只提交一个改图任务，引用刚确认的照片。拿到任务回执就可以说“改图任务已提交”，有成品再告诉主人。
4. 主人说“往前走十厘米”，底座连接正常时按这个目标执行。未连接就说明缺连接，停止没得到回执就说明停止未确认，测不到实际位移就如实说。主人不必从一句“好的”猜车究竟动了没有。
5. 主人说“你到周围转一圈”，小丫在当前地点附近巡视。已有地图就复用并观察变化；新区域就补记实际看到的局部地面。返回后能回答“刚才看到了什么”，回答能对应到本次巡视的时间、位置和观察记录。

## 实施设计

### 1. 从听见到说完（问题 4、6、9）

- 保留“一口气唤醒加指令”和“单独唤醒后再说”两种方式。界面分别显示待唤醒、已唤醒正在收音、正在听的临时文字、实际提交的整句。麦克风启动失败或被录像占用时，立即更新状态。
- 给普通对话、相机选择、急停分别配置收句策略。普通对话先试约 0.9～1.2 秒尾静音，放宽长句上限；用录音回放选择最终参数。只有已结束的整句可提交日常任务。“停”继续走已有本地快速路径，不等待模型。
- 为连续说话保留未提交的片段。若识别器在“你把这张照片”处给出终句，短暂等候续说；新语音到来即接上。长时间没有后半句时提示“想把这张照片怎么改？”，保留当前照片作为指代对象。切后台、取消、开始新会话要清掉旧片段。
- 对照少量常见口语和识别变体，只在对应场景处理。例如“重新拍一张”在审片时等价于“重拍”；“不要重拍”“确认一下这张照片里有什么”不得触发快门或保存。优先显示“听到：……”帮助用户发现错词。
- 增加可选的**同音频识别对照**。诊断页主动开始一次采样，展示本机转写；用户开启中转对照后，用同一段 WAV 调现有中转的 `/v1/audio/transcriptions` 和 `TeleAI/TeleSpeechASR`，并列显示文字、耗时、音量、削顶和丢块数。先验证这台手机和当前模型配置。219 中转用于诊断对照，是否切换日常识别结合这轮实测决定。若中转实测更准，可选用于唤醒后的自由描述；本地唤醒、停和相机短口令保持可用。中转超时显示来源并回到本地识别，同一句只能派发一次。诊断对照本身不执行指令。

### 2. 让用户听到真正的进度（问题 1、7）

- 移除 250 毫秒固定应答和没有新信息的通用提醒。收到问题时立即给视觉反馈。普通问答有公开回复就按完整短句读；工具有新阶段就读具体阶段，如“已拍到照片，正在识别画面”。内部推理、原始工具参数、逐个 token 不进扬声器。
- 朗读按“本轮会话、消息、阶段”去重。模型最终回复已读过的前缀不再重读。取消、切后台或新唤醒取代旧轮时，丢弃旧队列。工具启动、得到回执、文件下载完成是不同阶段，不能互相代替。
- 把对话连接和执行任务分开。基线的模型等待为连续 180 秒无数据或单次累计 900 秒，最多 3 次尝试；已有输出时重试受限。另有每轮最多 6 次模型请求及独立的拍照等待。分别记录触发哪种限制。达到模型轮次上限时先汇报已经完成的步骤和未完成项；长程工作交给可恢复的任务记录。
- Hermes 提交前持久化任务和幂等键。改图和视频沿用本地持久化任务标识，收到服务端编号后继续跟踪；没有服务端编号时保留待核对状态。拿到服务端编号后持续查询同一个任务；模型后续回复超时，仍报告已知状态。请求发出后若回执丢失，先查询或沿用原幂等键核对。执行结果不明时禁止通过重新发起移动、拍摄或生成来“补一次”。失败时要读出可行动的原因，如“服务器已收到任务，进度暂时取不到”。

### 3. 两次确认的相机（问题 3、4、6）

| 当前状态 | 说或点“确定” | 说或点“重拍” | 界面反馈 |
| --- | --- | --- | --- |
| 打开镜头中 | 等相机就绪，不提前排队按快门 | 无动作 | 显示相机启动状态或具体错误 |
| 实时取景 | 按一次快门，立即进入拍摄中 | 继续取景 | “摆好后，说或点确定拍摄” |
| 拍摄中 | 忽略重复输入 | 等照片返回 | “正在拍摄” |
| 照片审阅 | 保存当前草稿一次 | 丢弃草稿，回到实时取景 | “确定保存／重拍／取消” |
| 保存中 | 等本次保存结果 | 无动作 | 成功后回表情；失败保留草稿供重试 |

- 表情页快捷入口、模型的 `phone_photo` 工具、语音与触摸共用一个相机会话。取景和快门共享同一实时镜头。取景时显示真画面；拍后显示实际捕获的那一帧。按钮和语音可用条件一致。照片等待期间可以直接说“确定、重拍、取消”，不必重新叫名字。
- 失败和取消按阶段处理。没有相机权限、镜头占用、进入后台、开启录像、超时、旧回调晚到都不能保存错误照片。拍照占用镜头时保留收音；结束后恢复镜头所有者。系统语音提示不能被自己的麦克风识别成一次“确定”。
- 最终确认后把保存成功的作品编号设为当前照片；后续“把这张照片……”引用该编号。丢弃的草稿不进相册、作品列表或模型上下文。“看看周围有什么”沿用独立的后台取图工具，不要求主人摆姿势。

### 4. 让动作和口头回执一致（问题 2）

- 表情页和模型工具共用带单位的动作结构。支持“往前走10厘米”“往前走十公分”“向后退十厘米”；保留原有简单前进、后退。解析整句和单位，保留小数点，防止把 1.5 厘米误读成 15 厘米。超出可执行范围或含义不清，先说明限制，不擅自改距离。
- 明确“前”是表情面朝向；导航可沿后摄方向倒行，两者不能混用。普通短步沿用现有前后台、连接、障碍和悬崖保护。按方向区分标定数据。历史 450 毫秒后退约 6～7 厘米，不能据此保证向前在不同地面也一样准。
- 指定距离优先用可用且新鲜的位姿测量，并标记测量来源；普通表情页没有可靠位姿时，支持有标定依据的估时短步，回执明确“按目标估时执行，实际距离未测”。219 先采用实测后退短步的 6.5 厘米/450 毫秒作临时估时系数，前进方向仍待单独量测。单次范围 2～20 厘米，用户听到的回执明确距离未测。首轮地板实测正反方向各测多次，记录目标、实测距离、误差和停车情况，再决定可承诺的距离范围。
- 单次动作分别记录请求、驱动首次成功写入、被中断、请求停止、停止写入返回以及可用的实测位移。**写入成功只能证明通信完成。** 停止写入失败必须走异常和现有恢复路径；后续模型或 TTS 不能把异常改说成“走完了”。当前轮没有动作回执也不允许生成完成播报。要同时覆盖本地直通及模型选工具两条路径，包括流式播报早于工具返回的情况。

### 5. 用日常说法启动巡视（问题 8）

- 表情页和地图页共用附近巡视意图。“你到周围转一圈”“去附近看看再回来”“把房间逛一圈”都启动当前位置短巡视。“原地转一圈”属于转向；“去厨房拍张照再回来”属于指定地点任务；“刚才你去哪了”只查记录。不能把三者都映射成底座转一下。
- 有当前已定位地图时复用它。多地点且无法确定当前位置时，提示选择地点；没有地图时走局部建图准备。只打开准备页时说还差什么。连接、最低姿态、相机和定位一旦齐备，消费待执行请求一次；重复语音、切页和恢复不能开出第二个巡视任务。
- 沿用现有局部巡视边界（起点半径 80 厘米、最长 2 分钟）。已绘区域仍去观察，在任务记录中标记复用地图；新区域补本次有效覆盖。根据实际位移、观察点、开始返回和到点停车播报。失去定位或无可达路径时暂停并说明原因。未确认返回时不能说“回来了”。
- 对本轮巡视保存任务号、观察时间、地点、照片、分析状态、返回状态。照片分析慢可以先报告“已返回，照片正在整理”。重新唤醒或重开 App 后仍可询问同一份记录；未知区域、未探访房间不补写见闻。

## 一次集中验收

先用录音回放、模拟时钟、模拟工具和故障注入完成自动化，再打一个候选 APK。真机顺序如下；需要人工观察的项目集中到同一轮。

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 普通问答与打断 | 一口气叫名字并提问；长回复中打断 | 无固定开场；第一句完整回复先读；取消后不再读旧句。 |
| 取景、审片与改图 | 摆姿势，语音拍摄、按钮重拍，再用语音拍摄和保存；接着要求改背景 | 取景随人移动；两次确认职责明确；只保存一张，改图引用该张。另测一次取消和切后台。 |
| 自然停顿 | 同一句改图要求插入 0.5 秒、1 秒停顿，各重复三次；加一句超过 5 秒的长描述 | 对照原话逐字检查关键内容。一次意图只有一次提交，无半句误执行。 |
| 动作真值 | 先断连说前进，再连接，在平整空地对照尺标执行 10 厘米；另用模拟故障验证停止写失败 | 断连不发车，保护和失败能听懂；记录实测误差，无证据时绝不播报精确完成。 |
| 巡视与记忆 | 从表情页和地图页分别发起。覆盖已绘、新区域、多地点不明确三种起点。返回后再唤醒追问 | 只启动一个任务；等待有原因；能分清已返回、途中暂停和仍在整理照片。 |
| 网络与任务恢复 | 模拟首字节超时、输出半句断流、任务已接收后断网、恢复网络并重开 App | 能区分提交前失败和提交后进度未知；不重复执行；结果或错误可读。 |
| 远场对照 | 同一说话人在近处、1 米、2 米各说同一组唤醒、拍照、重拍、距离、改图和巡视短句。分别测安静、背景声和小丫播报中 | 分别统计唤醒命中、关键字/数字与方向正确率、截断数、误动作数、首个有效反馈耗时。用同一音频对比识别器，再判断是否值得换麦克风。 |

**交付记录**应列出实际 APK 版本、通过的自动化用例、未通过项及复现条件，另列真机误差和语音对照结果。此前 2.1.218 的视觉回放结果不计入本轮语音和行驶验收。

### 2.1.219 候选包的实现与验收状态

- 表情页中文自由对话用 1.1 秒尾静音和 25 秒最长语段。取景和审片时用 0.5 秒尾静音。改图句首被单独截断时，额外保留片段等待接续。具体识别率以真机为准。
- 模型连接超过 12 秒仍无可用内容时，按是否收到响应头播报等待阶段。已有工具回执时，后续断流仍会保留并汇报该回执。模型传输层继续沿用按推理请求重试的策略。
- 小范围巡视可从表情页直接进入。完成姿态确认后，若定位仍在恢复，保留待执行请求并在定位就绪时消费一次。
- TypeScript 和 12 组相关脚本已通过。原句回归覆盖拍照两次确认、重拍、半句接续、十厘米意图、停止写入失败、等模型进度，以及模型断流后的任务回执。远场收音、地上实际移动距离、相机预览和实体巡视留在同一轮真机验收。
- 语音诊断复用当前本地识别会话，结束采样后恢复原监听。拍摄中收到取消指令会结束当前草稿，晚到的快门结果不能进入下一次拍照会话。

Vosk 尾静音及最长语段参数依据上游实现。 [Vosk Recognizer::SetEndpointerDelays](https://github.com/alphacep/vosk-api/blob/master/src/recognizer.cc)

## 2.1.220 后续优化

- 照片工具确认保存或取消后，语音会话允许直接续说。新要求会打断旧模型续答，新的工具执行开始时重新按任务状态收音。
- 改图句首等待续说，提示后继续保留这张照片的指代，直到用户说完、重新唤醒或续聊窗口关闭。
- 同一张草稿重试保存沿用同一个作品编号。作品已保存但选中状态写入失败时，可以重试选中这张作品。
- 新一轮对话会检查请求归属，旧请求的晚到进度不能覆盖新请求；恢复模型上下文前等待原工具循环结束。
- 本轮维持 219 的距离执行范围和巡视能力。具体进展另按自动化与真机结果登记。
