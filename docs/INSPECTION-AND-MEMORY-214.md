# 214：巡查、到点拍照返回、见闻保存与续聊恢复

2026-11-17。用户要求先完成代码和自动检查，本轮不连接手机、不运行底座。真实跨房间、声音与视觉效果仍需集中验收。

## 能执行的任务

- **附近逛一圈**：使用当前已定位地图。在当前位置附近选择观察点，补记实际观察地面、停车拍照、沿实际轨迹返回；沿用80厘米半径和2分钟上限，不代表覆盖整个房间。
- **巡视各个登记房间**：沿真实已登记可达路线依次访问房间观察点，停车记录，再返回实际出发位置。单轮最多6个地点、往返40米、约9分钟，超限或不可达明确报告，不静默漏掉房间。
- **去厨房拍照再回来**：使用真实厨房地点编号与路线，到点自动拍照保存，不要求主人远程点确定；随后返回原出发位置。一般“帮我拍张照片”的确认/重拍流程保持原义。
- **补扫厨房等指定位置**：沿已知路线到该位置，补充本次实测地面格和照片，再返回。不清空其他地图，也不声称原地一张图能重建整间房的墙体。

语音与Pi工具入口为`inspect_home`，普通只去目的地使用原`navigate_home`。导航页支持“去厨房拍照再回来”“巡视各个房间”“重新扫描厨房”，并增加登记房间巡查和到点拍照按钮。操作前仍需连接、真实定位和最低姿态准备；打开准备页不表示已发车。

当前位置是否已有记录按附近实走路线或附近观察地面判断，不因手机里保存过别处地图就说这里已建图。已有记录先回应复用，未记录的当前位置说明补图。已建图仍拍摄观察，不把旧地图当作现在的房间情况。

## 任务与见闻分别持久化

每个任务记录稳定编号、地图、动作、原出发位置、已完成观察点和状态。每条见闻记录房间/位置、观察时间、真实照片作品编号、分析状态及摘要；照片和观察记录先落盘，再允许离开观察点。

导航相机由ARCore占用时，复用其相机帧保存独立JPEG，不再打开另一个Camera2摄像头。只有原生已到观察点、速度为零且收到停车回执后才取样。移动、会话切换或取消时不把旧画面当作新的成功观察。

返程使用同一原生控制任务，经过强制观察点后推进路线进度，避免往返重叠路段被误判仍在去程。原始出发位置可以在已知通道中间，不要求它预先登记为某个房间。地图变化、定位丢失、断连、用户停止仍会暂停；没有实际确认返回，不报告已回来。

照片分析在返程停车并退出导航后执行，不让车停在远处等待云端回复。分析任务也持久化，应用重开后可继续处理未分析照片；重开不会自行驱动车辆。分析失败可要求重新分析原任务照片，不发车、不重拍。

完成返回后自动回到表情页，恢复普通中文唤醒。分析完成后主动汇报；如果任务被取消或暂停，会明确说未确认返回。只描述镜头实际看见的内容，保留“没看清/无法判断”，不猜人物身份，不把过去照片说成现在实时情况。

左滑菜单新增**巡查见闻**，查看任务、房间、观察时间、摘要和原照片。说“刚才厨房有什么”“这次巡查看到了什么”，Pi通过`inspection_reports`查本地报告；查询不重新巡查。报告默认保留最近100项任务供查询，照片按作品存储，模型每轮只加载有界摘要，不一次塞入所有图片和完整报告。

## 60秒与记忆的关系

60秒只控制免唤醒续聊，不删除问答、任务、地图或见闻，不决定巡查运行时间。

- 同进程重新唤醒继续保留近期对话。
- 重开App后，从本地聊天库读取最新48条问答，按时间恢复有界摘要（最多12000字），作为历史资料提供给Pi，不重放其中的动作或旧工具请求。
- 巡查报告独立读取，保存观察时间和任务状态；模型上下文裁剪不会删除落盘报告。记忆读取失败会标记不可用，不声称全部记得。

## 当前仍有的边界

已登记房间巡查依赖实际存在的路线和定位。未知当前位置可做附近探索补图；没有接入全屋无标记定位、自动探索全部未知房间、自动分房及区域拆合。不能把这批任务编排当成这些能力已经完成。

每个登记地点只代表该镜头取得的视野，尤其镜头接近地板时，照片可能主要看到地板和家具下部。没有全景、没看见人时不能报告整个房间无人。不会为了拍照擅自抬头破坏导航安装标定。

中断任务保留已拍照片和已完成观察点；恢复行驶仍需用户恢复定位和姿态后显式继续。分析/问答恢复不等于自动恢复电机运动。

## 一次性验收

1. 在已有有效路线的地图登记或选中厨房，确认最低姿态和定位，说“去厨房拍照再回来”，或点相应按钮。
2. 检查出发提示、目标点停车拍照、实际返回出发位置、自动恢复表情和后续汇报。
3. 超过60秒重新唤醒，问“刚才厨房看到了什么”，再从巡查见闻页核对时间和照片。
4. 结束App进程后重开，再问原巡查与此前普通问答；应读到记录，但不会自动发车。
5. 另开任务，在途中停止或断连，检查保留的照片、未返回提示和定位后继续；不应把中断任务说成完成。

自动检查与构建结果完成后补充。本轮没有手机安装或实车结论。
