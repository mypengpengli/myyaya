# 家庭导航：建图、记住房间与集中验收

211是家庭导航的集中验收版本。房间命名、路线网络、地图编辑、连续局部控制的长路线衔接、暂停续行和重开后的定位检查已接入代码。自动检查不等于已在家中跑通跨房间：这批按用户要求不操作手机与底座，实际验收由用户集中完成。

210已通过单次局部绕罐实车验收；211新增整条家庭路线的组织流程，不能把210的结果算作跨房间已通过。

## 地图怎么理解

一张“我的家”地图包含书房、走廊和客厅，不要给每个房间分别新建地图。家庭图显示命名点、带领路线、当前位置、目的地和禁行区；不是自动生成完整墙体户型。底层表面点仍可查看。

房间名对应一个真实登记位置，门口也是实际位置。第一次带领经过这些位置时，它们之间的连接才成为可用路线。机器人以后沿这些连接行驶，沿途重新看地板、绕障；没有带领的空间不会因一句“这里能走”自动连成路线。

首版用固定照片辅助找回旧地图起点，之后以地板视觉累计移动和相机朝向跟踪。普通聊天里记住“客厅”这个词，不能代替地图定位。

## 第一次建立家庭地图

1. 左滑菜单 → **房间地图** → **家庭导航与地图编辑**。第一次打开建立“我的家”，此时先不扫描。已有家庭地图会打开原图；可用“打开地图”切换，用“新建地图”另建。
2. **首次扫描前**点“设置参照图”。选择固定平面照片的原图，或用后摄拍摄并校正四角，填写实物宽高。实物放在后摄可看见的位置并固定，不随机器人移动。不要把代金券随手挪到另一个房间后继续使用旧坐标。
3. 点“开始扫描”，让后摄看见原位置的完整参照图，等地图定位和地板视觉有效。纯色、暗光或视角不合适时可在装稳状态下缓慢挪动整机以建立观测。
4. 手动连接LOOI，把脖子压到最低、手机装稳。点击家庭导航里的“已最低，确认姿态”。镜头高度沿用最低姿态实测约8厘米，安装偏移沿用已填值；换安装方式需要重新标定。
5. 点“开始带领”，输入起点名，例如“书房”。按住“朝镜头走 / 左转 / 右转”带它沿地面行驶，松开停车；每次按住约3秒，随后可继续按。相机朝向是履带后退方向，不能把表情正面当行驶方向。不要拿高手机后继续按原8厘米高度建路线。
6. 经过房间、门口时点“记住房间/地点”“记住门口”，或说“这里是书房”“把这里记为书房门口”“这里是客厅”。每次记名会保存前一个命名点到当前点的实际带领路段。
7. 到客厅后点“结束带领”，填“客厅”；已在客厅记名且未再移动时也可直接说“结束带领”。保存后，地图应显示书房—门口—走廊—客厅的连接。

带领遇到定位中断会结束当前未完成路段，已保存的连接保留。恢复定位后从已有地点重新开始带领，不把中断前后的坐标强行接起来。首次可先录一条较短、平整的房间间路线，不需要先覆盖全屋。

## 地图与智能体编辑

- 点击图上的地点可改名、移到当前实际位置或删除；“编辑地图”也可列出全部地点。移动地点会清除相关旧路线，需要重新带领，不能拖动一个点就让旧路线跟着穿墙移动。
- 编辑菜单可停用/启用已记录的通道、删除禁行区。点击地图空白处可添加半径15厘米禁行区。禁行区按整车占地检查，不会被新的地板观测清掉。
- 普通对话里的Pi可用`home_maps`查询真实地图；`edit_home_map`记录、改名、移动或删除地点；`edit_home_passage`停用通道或管理禁行区。记录实际位置需要打开家庭导航并定位；返回“打开准备中”不表示已经保存。
- 可说“把客厅改名为大厅”“这里设为禁行区”。复杂编辑也可在普通对话中交给智能体，按已有地点/通道编号处理，不能凭空生成坐标与未走过的通道。

## 集中验收步骤

| 次序 | 操作 | 检查结果 |
| --- | --- | --- |
| 1 | 在图上核对房间名称与连接，改一个名字，再改回来 | 名称持久化，路线不乱移 |
| 2 | 处于登记起点或已带领路线附近，选择“客厅” | 地图出现黄色计划路线，机器人自动行驶并到点停车、汇报结果 |
| 3 | 沿途放可乐罐，重复去客厅 | 绕开后仍向原目的地行驶，不把避障完成误报成到达客厅 |
| 4 | 行驶时说“暂停”，停稳后说“继续” | 暂停有停车，继续时重新检查位置并规划到原目的地 |
| 5 | 行驶时说“取消导航” | 任务取消，后续观测不重新发车 |
| 6 | 完全挡住通道，或停用该通道，再要求去客厅 | 不编造另一条未带领的路线；说明原因并保留目的地供处理后继续 |
| 7 | 退出重开App，回到固定参照图附近，打开原地图并定位 | 原房间、路线、禁行区和旧任务仍在；定位前不会自动发车 |
| 8 | 恢复位置、连接和最低姿态后，继续旧任务或去另一地点 | 从当前已知路线位置规划，不沿用上次会话的裸坐标 |

不用USB或电脑。集中测试结束后，点“导出导航记录”，保存ZIP；失败时记录屏幕提示、目标地点和大致发生位置即可，不需要测每一小步。导出包含家庭地图、固定参照图、路线、任务和事件记录，不包含模型Key；相机/IMU录像另留手机本地，不自动上传。

## 页内语音

家庭导航页使用本地中文识别，普通聊天和抬头表情暂停，避免抢相机与底座。支持：

- “这里是客厅”“把这里记为沙发旁”“把这里记为客厅门口”。
- “开始带领从书房”“结束带领到客厅”。
- “去客厅”“暂停”“继续”“取消导航”“重新定位”。
- “把客厅改名为大厅”“这里设为禁行区”“已最低”。

停止仍可从屏幕底部“停止导航”触发。退出导航页后恢复原来的普通对话。噪声环境的识别与实际口头操作属于本批集中验收，不用自动仿真代替。

## 当前边界

- 本批跨房间路线、门口通过、重启后整条路线恢复及语音体验待现场验收。210单罐试验不能证明这些都已经可靠。
- 这是已带领路线网络；没有接入RTAB-Map无标记全屋重定位，也不是扫地机式自主探索覆盖全屋。先在固定参照图处找回位置，之后才能从已知路线附近出发。
- 每个教学连接最多30米，单次规划路线最多40米；连续任务约9分钟上限。局部规划按当前位置滚动，不再要求整条路线都在初始点1米内。途中仍可能停等新观测。
- 门槛、楼梯边缘、玻璃、杂乱电线和动态障碍的通用可靠性未验收。能压过1～2厘米实物，不代表视觉已经能可靠区分这些物体。
- 到点按当前视觉坐标进入约6厘米范围判断，非独立尺量精度；本批不自动转身面对用户。

## 实现与参考

沿用已验证的单一BLE连接、Kotlin原生20Hz控制/约10Hz写入、地板视觉里程计与本机相对深度模型。新增可版本化的家庭路线图和持久任务；整条路线共用一个原生任务，在行进中更新局部目标，不把每个小目标当成新任务重启。

参考[Nav2 Route Server的节点/边路线网络](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/core_servers/route_server/configuring_route_server/)及[路线图编辑工具](https://docs.nav2.org/rolling/tutorials/general_tutorials/route_server_tools/)，复用其分工思路，未在APK安装ROS。跨会话位置仍需明确恢复；[ARCore官方说明普通本地锚点只在本次应用实例有效](https://developers.google.com/ar/develop/anchors)，因此保存坐标本身不算重定位。

相关实现：`HomeAtlas`/`HomePoseTracker`/`HomeNavigationPanel`、`home-route.ts`/`home-mission.ts`、Pi家庭工具和导航页中文命令。自动检查覆盖图规划、禁行区、损坏文件、重新定位边界、转角、单任务三米路线、地图变化取消和失败清理。最终APK身份与实测状态见发布页，不把自动检查标成实车通过。
