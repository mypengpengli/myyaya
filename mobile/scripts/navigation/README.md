# Offline navigation audit tools

These scripts never connect to a phone, upload captures, or authorize motor movement. They require Python 3, JDK 17 and the compiled navigation-probe Kotlin classes plus Kotlin stdlib. The Python tools use only the standard library. Environment recordings stay outside Git.

1. `audit_replay.py INPUT --classes CLASSES --stdlib STDLIB.jar --jdk JDK --output OUT` converts bounded NDJSON depth samples to a temporary binary stream and calls the actual Kotlin `HybridDepth`, `DepthProjection`, `TerrainAnalysis` and `RoutePerception` classes through `TerrainReplayAudit.java`. Default `--fusion-slack-ms 0` reproduces the production time gate. A nonzero value (max 5ms) is an isolated offline counterfactual; original records and terrain timestamps remain unchanged. It rejects raw images near the age boundary so the experiment does not silently test a second time condition.
2. `explain_candidates.py OUT/frames.json --recording INPUT --output OUT/summary.json` counts connected ground components, the best supported circular footprint, never-expiring union upper bounds and spatial observations inside the current route sweep. The union ignores hazards and expiry and is never a usable motion map. Provide the original recording to audit camera heading; frame timestamps must match.
3. `footprint_counterfactual.py OUT/frames.json --frame N --output OUT/footprints.json` compares sampled oriented rectangles and 2cm straight sweeps against already-confirmed ground cells. It uses a separating-axis intersection check, physical padding and positive-area cell overlap. It does not establish reachability from the robot's current pose, stopping distance, acceptable pose uncertainty, or a motor command.

Do not feed experimental summaries into the robot controller. See [the recorded-data audit](../../../docs/NAVIGATION-CANDIDATE-AUDIT-2026-11-06.md) and [the selected development plan](../../../docs/INCREMENTAL-NAVIGATION-PLAN.md) for evidence and limitations.
